# Пошаговый деплой Telegram-бота на GitHub и Render

Ниже описан вариант для этого бота: он работает через Telegram long polling, поэтому
на Render нужен **Background Worker**, а не Web Service. Worker не должен слушать
HTTP-порт: он постоянно запускает `python bot/main.py` и получает обновления от
Telegram.

## 1. Проверьте файлы проекта

В проекте уже подготовлены:

- `bot/main.py` — код бота;
- `bot/requirements.txt` — зависимость `python-telegram-bot`;
- `render.yaml` — конфигурация Render Blueprint;
- `.gitignore` — исключение секретов и Python-кэша.

Секреты не записываются в код и не должны попадать в GitHub:

- `BOT_TOKEN` — токен Telegram-бота;
- `WEATHER_KEY` — ключ OpenWeatherMap.

Оба секрета уже добавлены в Secrets проекта Replit. Для Render их нужно добавить
отдельно в настройках Render, потому что секреты Replit автоматически туда не
переносятся.

## 2. Получите токен Telegram-бота

1. Откройте Telegram и найдите `@BotFather`.
2. Отправьте `/newbot`.
3. Задайте отображаемое имя бота.
4. Задайте username, который заканчивается на `bot`.
5. Скопируйте выданный токен.
6. Никому не отправляйте токен и не добавляйте его в файлы проекта.

Если токен стал известен посторонним, в `@BotFather` выполните `/revoke` и
обновите секрет `BOT_TOKEN`.

## 3. Получите ключ OpenWeatherMap

1. Зарегистрируйтесь на [OpenWeatherMap](https://openweathermap.org/).
2. Откройте раздел API keys в личном кабинете.
3. Создайте ключ или скопируйте существующий.
4. Убедитесь, что ключ активирован. Новый ключ иногда начинает работать не
   сразу.
5. Не публикуйте ключ в GitHub и не вставляйте его в `render.yaml`.

Бот делает запрос к Current Weather API с параметрами:

- `units=metric`;
- `lang=ru`;
- `q=<город>`.

## 4. Создайте репозиторий GitHub

### Вариант A — через GitHub-интеграцию Replit

1. Подключите GitHub в Replit, если он ещё не подключён.
2. Разрешите доступ к нужному аккаунту или организации.
3. Создайте новый приватный или публичный репозиторий.
4. Опубликуйте в него файлы текущего проекта.

Приватный репозиторий рекомендуется, если в проекте есть служебные файлы или
вы не хотите публиковать исходный код.

### Вариант B — командами Git

Откройте Shell в Replit и выполните команды из корня проекта:

```bash
git status
git add bot render.yaml .gitignore DEPLOY_RENDER_GITHUB.md
git commit -m "Add Telegram weather bot"
git branch -M main
git remote add origin https://github.com/ВАШ_АККАУНТ/ИМЯ_РЕПОЗИТОРИЯ.git
git push -u origin main
```

Если удалённый репозиторий уже был настроен, вместо `git remote add origin`
используйте:

```bash
git remote -v
git remote set-url origin https://github.com/ВАШ_АККАУНТ/ИМЯ_РЕПОЗИТОРИЯ.git
git push -u origin main
```

При запросе пароля GitHub используйте Personal Access Token с правом записи
в репозиторий, а не пароль от аккаунта. Не сохраняйте токен в файлах и не
публикуйте его в сообщениях.

### Проверка перед push

Убедитесь, что в список коммита не попали секреты:

```bash
git status
git diff --cached --name-only
```

В списке не должно быть `.env`, файлов с токенами и локальных виртуальных
окружений.

## 5. Подключите GitHub-репозиторий к Render

1. Откройте [Render Dashboard](https://dashboard.render.com/).
2. Нажмите **New → Blueprint**.
3. Подключите GitHub, если Render ещё не получил доступ к репозиторию.
4. Выберите репозиторий с ботом.
5. Render найдёт файл `render.yaml`.
6. Проверьте, что создаётся сервис типа **Background Worker**.
7. Нажмите **Apply** или **Create Blueprint**.

Конфигурация из `render.yaml` устанавливает зависимости командой:

```bash
pip install -r bot/requirements.txt
```

и запускает процесс командой:

```bash
python bot/main.py
```

## 6. Добавьте секреты в Render

В настройках созданного Worker откройте **Environment → Environment
Variables** и добавьте:

| Name | Value |
| --- | --- |
| `BOT_TOKEN` | токен из `@BotFather` |
| `WEATHER_KEY` | API-ключ OpenWeatherMap |

Нажмите **Save Changes**. После сохранения Render перезапустит Worker.

Не добавляйте секреты в `render.yaml`: записи `sync: false` специально означают,
что Render должен запросить их безопасно при создании или настройке сервиса.

## 7. Проверьте деплой

Откройте вкладку **Logs** у Worker. Успешный запуск должен закончиться
сообщением:

```text
Бот запущен и ожидает сообщения
```

Затем откройте бота в Telegram и отправьте:

```text
Погода в Алматы
```

Ожидаемый ответ содержит:

- город;
- температуру;
- ощущаемую температуру;
- описание на русском языке.

Также проверьте ошибки:

- `Погода в НесуществующемГороде` — бот вежливо сообщит, что город не найден;
- `Привет` — бот покажет подсказку по использованию;
- `Погода` — бот попросит указать город.

## 8. Автоматические обновления

После первого деплоя Render будет отслеживать выбранную ветку GitHub. Для
обновления бота:

```bash
git add bot render.yaml
git commit -m "Update weather bot"
git push
```

Render автоматически соберёт новую версию и перезапустит Worker.

Если автоматический деплой отключён, откройте Render → Worker → **Manual
Deploy → Deploy latest commit**.

## 9. Частые проблемы

### `BOT_TOKEN is not set` или `WEATHER_KEY is not set`

Перейдите в Render → Worker → **Environment** и проверьте названия переменных.
Они должны быть написаны точно: `BOT_TOKEN` и `WEATHER_KEY`, без кавычек и
пробелов.

### `Unauthorized` от Telegram

Токен неверный, отозван или вставлен с лишними пробелами. Получите новый токен
через `@BotFather` и замените значение `BOT_TOKEN` в Render.

### Город не найден

Проверьте написание города. Для неоднозначных городов можно дописать страну,
например `Погода в Париже, Франция`. Если проблема сохраняется для известных
городов, проверьте активность `WEATHER_KEY`.

### Render перезапускает Worker

Откройте логи. Повторные перезапуски обычно означают неправильный секрет,
ошибку установки зависимости или временную сетевую проблему. Worker не должен
слушать порт — это нормальное поведение для Telegram long polling.

### Telegram не отвечает

Проверьте, что в Render работает только один экземпляр этого бота. Одновременный
запуск двух копий с одним токеном может привести к конфликту получения
обновлений Telegram.

## 10. Итоговая схема

```text
GitHub (исходный код)
        ↓ push / новый commit
Render Background Worker
        ↓ BOT_TOKEN
Telegram Bot API
        ↓ WEATHER_KEY
OpenWeatherMap Current Weather API
```

GitHub хранит код, Render запускает процесс, а оба ключа хранятся только в
секретах Render и Replit, а не в репозитории.
